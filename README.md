# bot_game_book

Многопользовательская Telegram-игра «Книга в стиле испорченный телефон»:
игроки по очереди пишут главы книги через ИИ, каждый следующий автор видит
только короткое резюме предыдущей главы. Полный текст скрыт до финала.

## Стек

Python 3.12+, aiogram 3 (long polling, адаптер Telegram), MAX Bot API
(long polling, адаптер MAX), SQLAlchemy 2 + PostgreSQL 17,
APScheduler, OpenAI-совместимый LLM API, uv.

Архитектура мультиплатформенная: ядро игры (engine/llm/модели) не зависит
от мессенджера; доставка — через нейтральный транспортный слой
(`transport/`) и адаптеры (`adapters/telegram_adapter.py`,
`adapters/max_adapter.py`). Игроки из Telegram и MAX могут участвовать
в одной игре.

## Запуск (локальный, тестовый режим)

1. Postgres в Docker:

```bash
docker compose up -d
```

2. Зависимости:

```bash
uv sync
```

3. Конфиг: скопируй `.env.example` → `.env`, заполни `BOT_TOKEN`
   (у @BotFather) и/или `MAX_ACCESS_TOKEN` (настройки чат-бота в MAX),
   `MESSENGERS` — список платформ (`telegram,max`),
   `LLM_API_BASE` / `LLM_API_KEY` / `LLM_MODEL`,
   `ADMIN_USERNAMES` — свой username для админки. Платформа без токена
   молча пропускается.

4. Запуск бота (вручную, для тестов):

```bash
uv run bot
```

При старте создаются таблицы и загружается каталог стилевых карточек
(`seed/style_cards.yaml`).

## Как играть

1. Каждый участник: `/start` (регистрация обязательна)
2. Ведущий: `/newgame` — визард (стиль → тема → главы → слова → резюме →
   таймаут → участники)
3. Бот строит случайную очередь, дашборд приходит ведущему автоматически
4. Игроки пишут главы по очереди; ведущий: `/admin` (напомнить / передать
   ход / пауза / отмена)
5. После последней главы бот присылает книгу и цепочку резюме всем

## Тесты

```bash
uv run pytest
```
