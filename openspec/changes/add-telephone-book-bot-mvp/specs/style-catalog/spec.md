# Style-Catalog Specification

## Purpose

Каталог стилевых карточек писателей: источник стиля для генерации глав.
RAG не используется — модели знают популярных авторов, каталог даёт
стабильность и единообразие стиля между главами.

## Requirements

### Requirement: Seed-каталог стилевых карточек

**User Story:** Как ведущий, я хочу выбирать писателя из каталога,
чтобы получить предсказуемый и одинаковый стиль во всех главах.

#### Acceptance Criteria

1. Система SHALL загружать карточки из seed/style_cards.yaml при старте
   (идемпотентный upsert по slug)
2. Карточка SHALL содержать: slug, имя (ru/en), is_public_domain,
   description (5-6 предложений о стилевых приёмах), опционально excerpt
   (few-shot ≤500 знаков, только public domain), temperature
3. Карточки живых/несвободных авторов SHALL иметь excerpt = NULL, а их
   имя SHALL НЕ попадать в промпт генерации глав (только описание приёмов)

#### Scenario: Загрузка каталога

1. Бот стартует
2. Загрузчик апсертит карточки из YAML
3. Повторный старт не создаёт дубликатов

### Requirement: Собственный автор с генерацией карточки

**User Story:** Как ведущий, я хочу задать автора, которого нет в каталоге,
и получить стилевую карточку через ИИ.

#### Acceptance Criteria

1. WHEN ведущий вводит имя автора, не найденное fuzzy-поиском в каталоге
   THEN система SHALL предложить сгенерировать карточку мета-промптом
2. Сгенерированная карточка SHALL быть показана ведущему для подтверждения
   (кнопки «Взять»/«Перегенерить») до создания игры
3. WHEN игра создаётся THEN в games сохраняется СНАПШОТ карточки
   (style_card_text); последующие правки каталога НЕ влияют на игру

#### Scenario: Автор не из каталога

1. Ведущий пишет «Виктор Пелевин»
2. Fuzzy-поиск не находит совпадение
3. Бот генерирует карточку, показывает ведущему
4. Ведущий подтверждает — карточка снапшотится в игру
