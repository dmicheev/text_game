# add-telephone-book-bot-mvp

## Why

Нужна реализация игры «Книга в стиле испорченный телефон»: игроки по очереди
генерируют главы книги через LLM, видя только короткое резюме предыдущей главы.
Дрейф сюжета — ядро развлечения, поэтому полный текст обязан быть скрыт до финала.
Игра асинхронная и живёт днями → состояние только в БД, бот переживает рестарты.

## What

- Telegram-бот (aiogram 3, long polling): регистрация, визард настройки игры,
  цикл ходов, финальная публикация книги
- Каталог стилевых карточек писателей (seed YAML, ~40 авторов) + генерация
  карточки для произвольного автора через мета-промпт
- LLM-слой: OpenAI-совместимый адаптер, структурированный JSON-ответ
  `{title, chapter, summary}`, валидация (резюме ровно N слов, глава ±20%),
  максимум 1 внутренняя регенерация
- TurnOrchestrator: очередь игроков, таймауты, напоминания, единый путь
  пропуска хода (таймаут == ручной пропуск админом)
- Дашборд ведущего в Telegram: самообновляющееся сообщение со статусом игры
  и кнопками [Напомнить][Передать ход][Пауза][Отменить]
- BookCompiler: сборка финальной книги с раскрытием авторов, доставка участникам

## How

Python 3.12 + aiogram 3 + SQLAlchemy 2 (async/asyncpg) + PostgreSQL 17 (Docker)
+ APScheduler. Слои: presentation/telegram → core/engine → llm + db.
Контекст LLM-запроса O(1): system (снапшот стилевой карточки + правила) +
user (тема, резюме, twist игрока). Промпт глав никогда не содержит полный текст
предыдущих глав. Пропуск хода двигает указатель игроков, но не счётчик глав —
книга всегда с полным числом глав.

## Impact

Новый проект с нуля (репозиторий пуст). Затрагивает все будущие компоненты.
Развёртывание: тестовый период — ручной запуск на рабочем Mac (Postgres в
Docker), прод — VPS с тем же docker compose (отдельная задача после MVP).
