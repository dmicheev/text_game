# LLM-Chapter-Generation Specification (delta)

## Purpose

Двухстадийный конвейер генерации: глава как художественная проза (без JSON),
резюме — отдельным дешёвым вызовом. Раздельные модели для прозы и служебных
задач. Отрывки-образцы стиля и температура из карточки.

## Requirements

### Requirement: Проза без структурного режима

#### Acceptance Criteria

1. Стадия 1 SHALL генерировать главу обычным текстом (без response_format):
   первая строка — «## Название», далее текст главы
2. System-промпт SHALL подавать стиль как «твой почерк» + образец-отрывок
   (если есть) и ЗАПРЕЩАТЬ упоминание имени автора и слов «стиль»/«глава»
   в самом тексте
3. Температура прозы SHALL браться из карточки стиля (Game.style_temperature),
   по умолчанию 0.85
4. Провайдер SHALL поддерживать выбор модели на вызов: LLM_MODEL для глав,
   LLM_MODEL_FAST (fallback: LLM_MODEL) для служебных вызовов
5. Отклонение объёма более ±20% SHALL вызывать одну повторную генерацию,
   затем глава принимается как есть

### Requirement: Резюме отдельным вызовом

#### Acceptance Criteria

1. Стадия 2 SHALL сжимать уже написанную главу в резюме ровно N слов
   (модель LLM_MODEL_FAST, температура 0.2, JSON {"summary"})
2. Резюме SHALL ретраиться до 3 попыток независимо от главы; после —
   принудительная обрезка до N слов
3. Полный текст предыдущих глав SHALL по-прежнему НЕ передаваться в LLM
   (только тема, резюме, twist, номер главы)

### Requirement: Карточки стиля с образцами

#### Acceptance Criteria

1. Каталог SHALL наполнять excerpt (короткий стилизованный образец) для
   авторов public domain
2. При выборе карточки её текст для игры SHALL включать описание + образец
3. Game.style_temperature SHALL сохраняться при создании игры из карточки
